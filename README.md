# Tero Backend — باك اند وقاعدة بيانات جديدة بالكامل

هذا المشروع باك اند (Node.js + Express + Prisma + PostgreSQL) تم بناؤه من الصفر بحيث يطابق
كل نقاط الـ API (113 مسار) الموجودة بالفرونت اند المرفوع (`teromain.zip` — موقع Tero Network).

## ⚠️ ملاحظة مهمة جداً قبل ما تبدأ

تم بناء واختبار **صحة الكود بنائياً فقط** (فحص الأخطاء اللغوية بكل ملف، ومطابقة كل استدعاءات
قاعدة البيانات مع مخطط Prisma). لم أقدر أشغّل السيرفر فعلياً هنا لأن بيئة العمل (sandbox) بيها
قيود شبكة تمنع الوصول لـ registry.npmjs.org، فـ `npm install` ما اشتغل. يعني **لازم تشغّل الخطوات
أدناه بجهازك أو سيرفرك (أو أي بيئة عندها وصول إنترنت طبيعي) قبل ما تعتبر المشروع جاهز للاستخدام.**

كذلك، أي عملية تتعلق فعلياً بالبلوكتشين (توليد عنوان إيداع حقيقي، تنفيذ سحب على الشبكة، فحص أرصدة
محفظة ساخنة حقيقية، تجميع Sweep فعلي، فحص عقد RPC حقيقية) **غير منفذة فعلياً** — الكود يجهّز البنية
والجداول والمنطق حول هذي العمليات (تسجيلها، حالتها، إلخ) لكن الربط الفعلي بالبلوكتشين يحتاج مكتبة
مثل `ethers.js` أو `web3.js` ومفاتيح/RPC حقيقية يجب أن تُدار بعناية فائقة من طرفك، وهذا قرار تقني
وأمني لازم تاخذه أنت.

## المتطلبات

- Node.js 18 أو أحدث
- PostgreSQL 14 أو أحدث (سيرفر قاعدة بيانات فعلي — يمكن محلي أو سحابي مثل Supabase/Railway/Neon)

## خطوات التشغيل

```bash
# 1. تثبيت الحزم
npm install

# 2. انسخ ملف الإعدادات وعبّي القيم الحقيقية (رابط قاعدة البيانات، مفاتيح JWT...)
cp .env.example .env

# 3. أنشئ الجداول فعلياً بقاعدة البيانات (هذا هو إنشاء القاعدة الجديدة بالكامل)
npx prisma migrate dev --name init

# 4. عبّي بيانات أولية (حساب أدمن + خطط عضوية افتراضية + إعدادات أساسية)
npm run seed

# 5. شغّل السيرفر
npm run dev   # للتطوير مع إعادة تشغيل تلقائي
# أو
npm start     # للإنتاج
```

السيرفر يشتغل افتراضياً على `http://localhost:4000`، وتقدر تتأكد إنه شغال عبر:
`GET http://localhost:4000/health`

بيانات دخول الأدمن الافتراضية بعد الـ seed:
- البريد: `admin@teronetwork.com`
- كلمة المرور: `ChangeMe123!`

**غيّرها فوراً بعد أول تسجيل دخول عبر `/api/admin/auth/change-password`.**

## حذف القاعدة القديمة والبدء بوحدة جديدة نظيفة

بما إنه ما كان عندك وصول لأي باك اند أو قاعدة بيانات قديمة فعلية، هذا المشروع **هو القاعدة الجديدة
نفسها من الصفر** — ما فيه شي قديم تحذفه لأنه ما كان موجود أصلاً بمتناول اليد. إذا لاحقاً حصلت وصول
لقاعدة بيانات قديمة فعلية (مثلاً بعد ما تربط استضافة أو Supabase)، الخطوات تكون:

1. تسوي نسخة احتياطية من القاعدة القديمة (لو تحتاج البيانات لاحقاً).
2. تحذف القاعدة القديمة بالكامل من لوحة تحكم الاستضافة (أو `DROP DATABASE`).
3. تنشئ قاعدة بيانات فارغة جديدة بنفس المزوّد.
4. تحط رابط الاتصال الجديد بـ `DATABASE_URL` داخل `.env` هذا المشروع.
5. تشغّل `npx prisma migrate dev` حتى ينشئ كل الجداول من هذا المخطط بالقاعدة الجديدة.

## هيكل المشروع

```
prisma/
  schema.prisma       # مخطط قاعدة البيانات الكامل (32 جدول)
  seed.js              # بيانات أولية
src/
  app.js               # إعداد Express والميدل وير وربط كل الراوتات
  server.js             # نقطة تشغيل السيرفر + Socket.IO
  config/               # إعدادات البيئة وعميل Prisma
  middleware/           # المصادقة (مستخدم/أدمن)، معالجة الأخطاء، التحقق من المدخلات
  routes/                # كل الـ 113 مسار API مقسّمة حسب الموضوع
    admin/                # مسارات لوحة تحكم الأدمن
  utils/                 # أدوات مساعدة (JWT، الأكواد، صيغة الردود)
```

## نقاط API المُغطّاة

كل الـ 113 مسار اللي تم اكتشافها من كود الفرونت اند (`/api/auth/*`, `/api/user/*`, `/api/wallet/*`,
`/api/membership/*`, `/api/referrals/*`, `/api/tasks/*`, `/api/notifications/*`, `/api/transactions`,
`/api/storage/*`, `/api/admin/*` بكل تفريعاتها: users, tasks, membership-plans, treasury, hot-wallet,
sweep-manager, gas-management, rpc-monitor, honor-points, leaders, notifications, site-settings,
withdrawals, maintenance, referral-commission-config, wallet-change-requests...) منفّذة بمنطق عمل
منطقي مبني على تخمين معقول لشكل البيانات. **راجعها وعدّل النسب/الحدود/الشروط المالية (عمولات
الإحالة، نسب الأرباح اليومية، حدود السحب...) لأنها قيم افتراضية وضعتها كنقطة بداية فقط.**

## أمان — قبل أي استخدام حقيقي

- غيّر كل القيم بـ `.env` (خصوصاً مفاتيح JWT وكلمة مرور الأدمن).
- فعّل HTTPS خلف السيرفر (عبر Nginx أو مزود الاستضافة).
- راجع منطق السحب/الإيداع جيداً قبل ربطه بأي عملية مالية حقيقية على البلوكتشين.
- لا تشارك ملف `.env` أو مفاتيح المحفظة الساخنة مع أي جهة.
